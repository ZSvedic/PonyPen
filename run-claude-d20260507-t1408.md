## What I built

- **`src-claude/ponypen-core.js`** — pure JS headless core. Exports `createGame(levelText, options)` and `parseLevelFilename(path)`. Owns: parsing, validation, BFS reachability with portal teleport, scoring with item bonuses (`C +3`, `A +10`, `B -5`), `enclosedMap`, and event-emitting actions (`toggleRock`, `reset`, `score`).

## Important decisions

- **"Suboptimal" rule.** The headless spec says: *"If a solution's rock removal still encloses the pony: `Level has a suboptimal solution.`"* Read literally that would reject `03-bees_teleport-19.txt` (removing the rock between pony and bee leaves the pony enclosed but lets a bee in). I interpreted "still encloses" as "the rock is dead weight" and implemented the test as `probeScore.score >= solvedScore.score ⇒ suboptimal`. This passes all bundled levels and matches the `(N-rocks-maxScore).txt` filenames.
- **Edge escape.** Implemented as: BFS marks pony as escaped if any reachable passable tile is on the grid boundary (row 1, row H, col 1, col W). Water and rock tiles never become reachable, so water on the edge does not count as escape. Verified against `52-bad_leak-1.txt` (pony reaches the bottom-row grass and escapes).
- **Portals.** When BFS visits a `@` tile, it enqueues every other `@` tile. Verified by `03-bees_teleport-19.txt` peak score 19 (reaches the `A` cluster only via the teleport).
- **`createGame` input.** API is `createGame(levelText, options)`. The CLI extracts `name` and `maxScore` from the filename via `parseLevelFilename` and passes `name` only — `maxScore` is computed from the solved board so a mis-named filename doesn't change scoring. Filename `maxScore` is shown in the web "BEST" label and in the dropdown.
- **Phaser via CDN.** `code-spec.md` says "minimal dependency tree, `bunfig.toml` `minimumReleaseAge = 604800`". Phaser is declared in `package.json` for the install age policy, but the page loads it from `cdn.jsdelivr.net` so the web shell runs without a build step.
- **Tile coloring.** Followed `web-spec.md` literally: water `#064b8e`, rock `#5f6872`, grass `#2f8f3a`, enclosed `#f1c40f`. Water and rock tiles never turn yellow, regardless of `enclosedMap` (matches the prose; see remaining issues for T006 conflict).

## Remaining issues / spec ambiguities

- **T006 background color table.** The Gherkin lists `r1c2` and `r1c3` as `gray` and `r2c1`, `r2c3`, `r3c2` as `yellow` for `01-minimal-1.txt`. With my reading of `web-spec.md`, those cells are water (`=`, dark blue) and rocks (`#`, gray). I implemented the prose; the table seems off. Worth confirming whether the table or the prose is canonical.
- **Trailing whitespace in CLI snippets.** `cli-spec.md` shows lines like ` \ 1 2 3 4 5 ` and an empty space-padded line between board and "Placed". I render without trailing spaces — tests in T002 / T003 / T004 use `display contains` which still passes, but a strict line-equality test would diverge.
- **Suboptimal phrasing.** The spec sentence ("rock removal still encloses the pony") would benefit from rewording, e.g. *"a rock is unused if removing it does not lower the score"*. Otherwise readers will reproduce my initial bug.
- **Out-of-rocks message.** Spec only specifies the grass-only message; I added `"Out of rocks: N max."` for the over-budget case.
- **Web stats label "BEST".** Web spec lists "best score" as a required label but doesn't define how it's seeded or persisted. I seed it from the filename's `maxScore` and update if the player exceeds it during the session; nothing persists across reloads.
