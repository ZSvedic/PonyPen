## Important decisions

- Kept the core file-I/O free. The core only accepts level text and optional metadata.
- Added a small known-level metadata map in the core so direct headless use can still expose the expected level names and scores for the provided spec levels.
- Treated portals as a connected teleport network: once any reachable portal is entered, all portals become reachable.
- Updated `scoreResult` after every toggle/reset so the CLI and web shells can show live score state without duplicating rule logic.
- Implemented undo/redo in the web shell as shell-level move history, not core-level history.
- Used the existing `spec/web-mockup.txt` file as the palette source because the spec text references `web-mockup-claude.txt`, which does not exist.

## Remaining issues

- I did not run a real browser automation pass; the web shell was verified through file/module tests and HTTP smoke checks, not full visual/browser interaction automation.
- The CLI interactive status line uses `-` instead of the spec’s displayed em dash to stay closer to the “ASCII output” requirement.
